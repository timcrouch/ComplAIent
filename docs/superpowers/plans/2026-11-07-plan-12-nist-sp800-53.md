# Plan 12 — NIST SP 800-53 Rev. 5 (Moderate baseline) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The control library ships NIST SP 800-53 Rev. 5 as a fifth framework, limited to the SP 800-53B Moderate baseline's 177 base controls. Each has an own-words title, belongs to its family group, and is mapped to at least one library control. An organisation with US federal, contractor or FedRAMP exposure can choose it in Setup, filter the library by it and get a Statement of Applicability grouped by family.

**Why:** issue #20. CSF 2.0 (Plan 10) covers outcomes; US auditors and FedRAMP ask for the 800-53 controls themselves. Spec: `docs/superpowers/specs/2026-11-07-nist-sp800-53-design.md`.

**Architecture:** content, a small loader extension, one new control, one line in the SoA export, the library's own tests and docs.
- The app is data-driven (as in Plan 10). No web, database schema or migration change. The one API change: the Excel SoA export names its group column "Family" for `nist-sp800-53-r5` (`apps/api/src/reports/render/common.ts`, the level-name map from #19).
- New content: `content/frameworks/nist-sp800-53-r5.json` (framework, version, family `groups`, 177 requirements, one per line) and `content/mappings/nist-sp800-53-r5.json` (mappings from existing controls).
- `load.ts` reads the manifest's `mappings` files and merges them into the controls, so the loaded `LibraryContent` keeps its shape and `validateLibrary`, sync and the grouping validation (#19) work unchanged.
- `references.ts` gains `NIST_SP800_53_MODERATE_REFS` (IDs only). `themes.ts` gains an `sp80053` list per theme that partitions the 177 refs.
- Existing installations get the content through `pnpm db:seed` (ADR-0008).

**Tech Stack:** as in Plan 9. No new dependencies.

**Source:** NIST's OSCAL content (github.com/usnistgov/oscal-content, `nist.gov/SP800-53/rev5/json/`), retrieved 2026-11-07: `NIST_SP-800-53_rev5_MODERATE-baseline_profile.json` for the baseline (the `with-ids` without a dot are the base controls) and `NIST_SP-800-53_rev5_catalog.json` for the order, the family names and the control statements, which were used for paraphrasing only. The OSCAL files are not committed. Rulings for this plan are P12-R*.

## Rulings

- **P12-R1 Scope.** Moderate baseline, base controls only: 177 controls, 18 families (no PM, no PT). Enhancements and other baselines are a later issue.
- **P12-R2 One framework file.** #19 formats framework files at Prettier `printWidth` 180, so each requirement sits on one line and 177 requirements plus 18 groups stay well under 500 lines. No part files are needed (a part-file loader was considered and dropped as unnecessary).
- **P12-R3 Mapping files.** The manifest may list `mappings` files: `{ "framework": "<version key>", "mappings": [{ "control": "ACC-01", "ref": "AC-2" }] }`, one entry per line. The loader appends each entry to the named control's mappings; an unknown control code is a load error. Existing control files and their tests stay untouched, and no control file grows. Duplicates and unknown refs are caught by `validateLibrary` as before.
- **P12-R4 Groups.** One level: the 18 families present, key = family ID (`AC`), title = the official family name. Requirements carry `group`; groups in catalogue order; a group's requirements are contiguous (the #19 contract).
- **P12-R5 One new control.** **ACC-10** (category `access`, `controls/access.json`), "End idle or finished sessions so an open login cannot be reused": systems end sessions after inactivity, on sign-out and at a maximum length. It covers AC-12 (session termination), which no control did (PHY-06 is the physical clear screen), and also maps SC-10 and ISO A.8.5 (its required inline mapping). Every other ref fits an existing control in its theme; the weakest fits are named in Review Focus.

## Global Constraints

- **Keys and labels, exactly:** framework key `nist-sp800-53`, name `NIST SP 800-53`, publisher `NIST`, version key `nist-sp800-53-r5`, version label `Rev. 5 (Moderate baseline)`. The manifest lists it after NIST CSF. `libraryVersion` is one patch beyond #19's.
- **References** are the official upper-case IDs, catalogue order within family, families in catalogue order, exactly the 177 in `NIST_SP800_53_MODERATE_REFS`. No enhancements (no `AC-2(1)`).
- **Titles are our own words (ADR-0008):** one sentence, capital, full stop, 5 to 16 words, saying the same thing as the control. Not NIST's sentence lightly edited, and no "The organization shall". No `fullText`.
- **Summary** at most 300 characters, plain language: who it is for (US federal agencies, government contractors, cloud providers seeking FedRAMP; widely asked for by US auditors) and that this is the Moderate baseline.
- **Every ref is mapped**, by a control of the theme the partition assigns it to. Extra mappings to other themes are allowed where clearly right. Prefer fewer, defensible mappings.
- **No CSF ↔ 800-53 cross-mappings**, no change to the AI mock, the demo company (stays ISO 27001, NIS2, GDPR) or app code.
- **Every content and TS file under 500 lines.**
